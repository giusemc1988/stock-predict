# BayReady update did not reach the shop PC
- **Date / who:** 2026-11-12, claude
- **Problem:** v2.73 was built and installed on Windows CN88 only. Chanh was at the shop on the Ubuntu PC, still on v2.69, and Ubuntu `~/Downloads` had no new zip. A cloud thread could not write to Windows Downloads or the install folder (folder access denied) or reach Ubuntu (ssh "Network is unreachable"), so Chanh was handed copy steps.
- **Cause:** nobody owned "put the build on BOTH machines". Ubuntu's `bayready-updater.py` pulls `bayready-latest.zip` from CN88 over Tailscale (`bayready-serve.py`, port 8765, file `C:\Users\chanh\milo-shared\bayready-latest.zip`), the release server, and `~/Downloads`. That file was stale at v2.48. Windows `bayready-updater-win.ps1` reads `C:\Users\chanh\Downloads` and the release server instead. Also `stage68\src` is stale (2.70): the newest `stageNN\src` is the source.
- **Fix:** whoever builds the zip writes it to `milo-shared\bayready-latest.zip` AND hands it to Milo, who puts it on both machines. Chanh only presses Settings, Updates, Update, then Reload and F5 (a page keeps the old version string until F5). Never give Chanh copy steps.
- **Check:** `bayready-latest.zip` manifest version equals the new version; Ubuntu `/home/cmn/Downloads/bayready/manifest.json` and Windows `Desktop\BayReady\manifest.json` both match; the panel footer shows the new version after F5.
